# 처음 보시는 분께 (개요)

## 서비스 소개
경북 상주 중앙시장 근처 동네 미용실 "은파미용실"의 공식 홈페이지입니다.
검색해도 주소밖에 나오지 않아 새 손님이 가게를 판단할 수 없던 문제를, **가격 공개 · 원장님 소개 · 길 안내 · 블로그**로 해결합니다. 주 고객층은 40~70대 여성이라 큰 글씨·큰 버튼·높은 명도 대비를 지키고, 한국어·영어·일본어 3개 언어를 지원합니다.

## 주요 기능 (구현 완료)
| 화면 | 기능 |
|---|---|
| 홈 | 첫 문구(후보 3개 중 선택 또는 직접 입력), 가격표, 미용실 소개, 최근 블로그, 영업시간·휴무일·주차 안내, 이벤트 배너 |
| 미용실 소개 | 원장님 인사말(여러 개 중 방문 때마다 무작위 1개), 경력 43년, 매장 사진 |
| 블로그 | 계절별 모발 관리·파마 후 관리 등 글 목록과 상세 (한국어 본문이 기본, 영어·일본어는 선택) |
| 찾아오시는 길 | 네이버 지도·네이버 내비 길 안내(키가 없으면 지도 이미지로 대체), 전화·카카오톡 상담 버튼, 영업시간·휴무일·주차 |
| 관리자(`/admin`, 한국어) | 가격표 한 화면 인라인 편집·순서 변경·숨기기, 블로그 작성, 원장님 소개, 사이트 설정(주소·전화·영업시간·주차·지도), 이벤트, 휴지통 복구 |
| 공통 | 3개 언어(`/ko` `/en` `/ja`), 모바일 하단 고정 바(전화·길 찾기), 전화·길 찾기 클릭 수 집계(개인정보 저장 없음), 구조화 데이터(JSON-LD)·sitemap·hreflang |

**의도적으로 만들지 않은 것:** 자체 예약·후기 기능 (개인정보 취급과 운영 부담을 피하고 네이버 서비스를 활용)

## 기술 스택
| 구분 | 내용 |
|---|---|
| 언어·프레임워크 | Ruby 3.4 / Ruby on Rails 8.1 (Hotwire: Turbo·Stimulus) |
| UI | 순수 CSS (프레임워크 없음, 색은 `:root` 변수에 집중), importmap, Propshaft |

| 품질 | RuboCop, Brakeman, bundler-audit, GitHub Actions(CI) |
| 공개 (예정) | AWS Lightsail 서울 1GB + Caddy(자동 HTTPS) + DuckDNS + Litestream(S3 백업) |

## 로컬에서 실행하는 방법
Docker Desktop만 있으면 됩니다. Ruby를 따로 설치할 필요는 없습니다.
```bash
docker compose up -d --build   # 처음 실행 시 DB 생성·마이그레이션·시드가 자동으로 진행됩니다
```
- 손님 화면: http://localhost:3001/ko (`/en`, `/ja`도 가능) / 관리자: http://localhost:3001/admin
- 개발용 임시 관리자 계정은 `admin@example.com` / `change-me-please` 입니다. **`.env`에서 반드시 바꾸세요.** (`.env.example`을 복사해서 사용, `.env`는 저장소에 올리지 않음)
- 로그 보기 `docker compose logs -f web` / 멈추기 `docker compose down`
- 다른 컴퓨터로 옮길 때는 코드 외에 **DB 파일(`db/*.sqlite3`)과 업로드 이미지(`storage/`)** 도 함께 옮겨야 입력한 내용이 그대로 보입니다. (Git에 포함되지 않음)

## 알려진 제한과 앞으로의 과제
- 영어·일본어 번역은 **초안**입니다. 공개 전에 전문 검수가 필요합니다.
- 아직 배포 전이라 신규 고객 확보 효과는 검증하지 못했습니다.
- 무료 서브도메인(DuckDNS)은 독립 도메인보다 신뢰감·검색 노출에서 불리할 수 있어 정식 운영 시 교체를 검토합니다.
- Litestream은 DB만 백업합니다. **업로드 이미지는 별도로 백업**해야 합니다. (운영 절차: [docs/runbook.md](docs/runbook.md), 비용: [docs/server-cost.md](docs/server-cost.md))

- 한국어 · 영어 · 일본어 표시 (영어·일본어는 초안)
- 네이버 지도 길 안내, 전화·카카오톡 상담 버튼
- 구조화 데이터(JSON-LD), 이미지 자동 축소·WebP 변환

# 8. 이 서비스의 우려사항과 대책

## 우려사항 ① 블로그 갱신이 멈출 가능성
- **원인:** 가게 운영과 병행하는 원장님이 글 쓸 시간이 없을 수 있다. (가정)
- **대책:** 짧은 글 중심으로 하고 초안은 본인이 도와준다. 【TODO】 실제 운영 방침 확정.

## 우려사항 ② 배포 전이라 효과를 아직 검증하지 못한 점
- **문제:** 신규 고객 확보라는 목적의 달성 여부를 아직 측정할 수 없다.
- **대책:** 오픈 후 "어떻게 알고 오셨어요?"를 기록하고, 전화·길 찾기 버튼 클릭 수를 확인한다. (클릭 수 집계는 구현되어 있고, "어떻게 알고 오셨어요?"는 수기 기록)

## 우려사항 ③ 무료 서브도메인(DuckDNS) 사용
- **문제:** 신뢰감, 검색 노출, 서비스 지속성에서 독립 도메인보다 불리할 수 있다.
- **대책:** 정식 운영 시 독립 도메인으로 교체할 수 있는 구조로 두고, 교체 계획을 문서화한다.

# 9. 앞으로의 방향
- **기능:** 예약과 후기는 자체 개발하지 않고 네이버 예약·네이버 플레이스와 연동한다. (네이버 예약 요금과 결제 수수료 조건은 파트너센터에서 직접 확인)
- **콘텐츠:** 네이버 플레이스 등록·운영, 블로그 콘텐츠 확대.
- **언어:** 영어·일본어 번역의 전문 검수.
- **운영:** 배포(Lightsail), 독립 도메인 교체, 이미지 백업 자동화.

# 10. 기술 스택 (수단으로서의 기술)

## 10-1. 사용 기술
- **프레임워크:** Ruby on Rails 8.1 (Hotwire: Turbo / Stimulus)
- **데이터베이스:** SQLite (운영은 Litestream으로 연속 백업)
- **개발 환경:** Docker
- **운영 (예정):** Caddy, AWS Lightsail, GitHub Actions

Rails(Hotwire)는 서버에서 HTML을 만들어 SEO와 초기 표시에 유리하고, 관리자 인라인 편집(Turbo Stream)에 잘 맞아 선택했습니다. 선택의 상세한 이유와 대안은 [docs/adr/](docs/adr/)에 있습니다.

| 후보 | 채택 | 이유 |
|---|---|---|
| SQLite (WAL) | 채택 | 쓰기 주체가 원장님 1명이라 충분하고 운영이 단순하다 |
| PostgreSQL | 불채택 | 이 규모에서는 컨테이너·메모리 부담이 크다 (동시 쓰기가 늘면 전환 검토) |
| Rails + Hotwire | 채택 | SEO·초기 속도에 유리, 관리자 인라인 편집에 적합 |
| SPA (React 등) | 불채택 | 페이지 수가 적어 번들러·API 분리 비용에 비해 이점이 적다 |
| 자체 예약·후기 기능 | 불채택 | 개인정보 취급과 운영 부담. 네이버 예약·플레이스를 활용 |
