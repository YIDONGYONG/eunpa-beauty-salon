## ADR 0001: SQLite を本番でも使う / 운영에서도 SQLite 사용

状態 / 상태: 採用 / 채택 (2026-10)

### 背景 / 배경
- 町の美容室サイト。アクセスは1日数十〜数百、書き込みは管理者1人のみ。月額コストは「ほぼ無料」が条件。
- 動かす環境は 1GB クラスの小さな VM（AWS Lightsail 等）。PostgreSQL を同居させるとそれだけで数百 MB を使う。
- 동네 미용실 사이트: 읽기 위주, 쓰기는 관리자 1명. 월 비용은 거의 0원이 조건. 1GB급 작은 VM(AWS Lightsail 등)에서 PostgreSQL을 같이 돌리면 메모리가 부족.

### 決定 / 결정
SQLite（WAL モード、`busy_timeout=5000ms`、`synchronous=normal`）を開発・本番の両方で使う。Rails 8 標準の Solid Cache / Queue / Cable も SQLite で動かす（Redis 不要）。

### 検討した代替案 / 검토한 대안
| 案 | 採用しなかった理由 |
|---|---|
| PostgreSQL（同一VM） | メモリ消費が大きい。管理が1サーバー2プロセスに増える |
| Cloud SQL / マネージドDB | 無料枠なし。月額が目的の予算を超える |
| PostgreSQL（外部の無料プラン） | 海外リージョンで遅延、無料枠の停止・消去リスク |

### 結果・トレードオフ / 결과와 한계
- 利点: 運用がファイル1つ。バックアップは Litestream で連続複製（ADR 0002）。開発と本番が同じDB。
- 制約: 書き込みは直列（同時に1つ）。サーバーは1台のみ。スケールアウトできない。
- **切り替えの目安**: 管理者が複数人で同時編集する、サーバーを2台以上にする、書き込みが常時ある、のいずれかになったら PostgreSQL へ移行する（ActiveRecord を使っているのでコード変更は小さい）。
- 한계: 쓰기가 직렬. 서버 1대. 관리자 여러 명이 동시에 편집하거나 서버를 늘려야 하면 PostgreSQL로 전환.

## ADR 0002: Litestream で S3 にバックアップ / Litestream으로 S3에 백업

状態 / 상태: 採用 / 채택 (2026-10)

### 背景 / 배경
SQLite は「ファイル」なので、ディスクが壊れるとデータが全て消える。スナップショット（日次）では最大1日分を失う。

### 決定 / 결정
- Litestream で primary DB の WAL を約10秒ごとに AWS S3（ソウル）へ複製（GCS も同じ設定で可）。保持期間 72 時間。
- 複製するのは **primary のみ**。cache は再生成できる、queue / cable は一時データのため対象外（`config/litestream.yml`）。
- 認証は **そのバケットだけ**に権限を絞った IAM ユーザーのキー（`.env` に保存。AWS ルートのキーは使わない）。
- コンテナ起動時に DB が無ければ自動で復元（`bin/docker-entrypoint`）。
- **画像ファイル（Active Storage）は Litestream の対象外。** `/var/lib/eunpa/files` を別途バックアップする（docs/operations.md 参照: 日次の `gcloud storage rsync`）。

### 復元テスト / 복원 테스트
`deploy/restore-test.sh` で「ディスク消失 → 再起動 → 自動復元」を実機（Docker）で確認済み。結果は docs/operations.md に記録。S3 では URL を `s3://...` に変えるだけ（GCS も同様）。

### 代替案 / 대안
- 日次の `sqlite3 .backup` + cron: 最大24時間分の損失。手順が増える。
- Cloud SQL 自動バックアップ: 無料枠なし（ADR 0001）。

## ADR 0003: 多言語は韓国語＋英語の2言語に限定 / 다국어는 한국어+영어 2개로 한정

状態 / 상태: 採用 / 채택 (2026-10)

### 背景 / 배경
当初は ko / en / vi / ja の4言語を想定したが、翻訳を専門家に確認する手間と費用に対して利用者が少ない。主な客層（40〜70代の地元の方）は韓国語、英語は外国人客・採用担当者向け。

### 決定 / 결정
- 公開URLは `/ko` `/en`。固定文言は `config/locales/{ko,en}.yml`、DBの内容は `*_ko` / `*_en` 列（`Translatable`）。英語が空なら韓国語を表示（フォールバック）。
- ブログ本文と院長紹介の英訳は **構造だけ用意して任意入力**。
- 英語の文言は **草稿**。公開前にネイティブ校閲が必要。
- vi / ja は削除（マイグレーション `RemoveVietnameseAndJapaneseColumns`。**元に戻せない**ためバックアップを取ってから）。

### 将来 / 앞으로
言語追加は ADR のとおり「ロケールファイル + `_xx` 列 + ルート制約」の3点。必要になった時点で再検討する。
(README の「新しい言語の追加方法」を参照)

### 개정 / 改訂 (2026-11): 일본어(ja) 추가
- 일본어 손님 대응을 위해 `ja` 를 추가. 공개 URL `/ja`, 고정 문구 `config/locales/ja.yml`, DB 번역은 `*_ja` 컬럼(마이그레이션 `AddJapaneseColumns`).
- 일본어는 **초안**이며 네이티브 검수 필요. 비어 있으면 한국어로 대체(기존 규칙 동일). vi 는 계속 제외.

## ADR 0004: 本番は Docker（Rails+Litestream コンテナ + Caddy）/ 운영은 Docker

状態 / 상태: 採用 / 채택 (2026-10)

### 決定 / 결정
- 本番は Rails+Litestream の **コンテナ1つ**（+ HTTPS 用の Caddy。DuckDNS は Cloudflare の背後に置けないため）: Puma（ワーカー無し・スレッド3）の中で Solid Queue を動かし（`SOLID_QUEUE_IN_PUMA`）、`litestream replicate -exec` が Rails を子プロセスとして起動する。
- **ビルドは GitHub Actions**（テスト → イメージ作成 → GHCR へ push）。VM では `docker compose pull && up -d` だけ。1GB の VM で `docker build` や `assets:precompile` を実行しない。
- イメージは multi-stage（コンパイラは最終イメージに入れない）、非 root（UID 1000）、`libjemalloc2` でメモリ断片化を抑える。`config/master.key` は `.dockerignore` で除外（イメージに秘密を入れない）。
- 秘密値は VM の `.env`（`deploy/env.production.example`）と GitHub Secrets のみ。

### 代替案 / 대안
| 案 | 理由 |
|---|---|
| Kamal | 強力だが、1VM・1コンテナには機能過多。学習コストと依存が増える |
| Kubernetes / Cloud Run | コスト・複雑さが目的に合わない（Cloud Run は SQLite の永続化と相性が悪い） |
| VM に直接 Ruby を入れる | 環境差・パッチ管理が属人化する |

### メモリ実測 / 메모리 실측
`deploy/measure-memory.sh`（メモリ上限 700MB）: 起動直後 約 214MB、1000 リクエスト後 約 266MB。

## ADR 0005: 院長のあいさつ文を複数持ちランダム表示 / 원장님 인사말을 여러 개 두고 무작위 표시

状態 / 상태: 採用 / 채택 (2026-10)

### 決定 / 결정
`owner_greetings` テーブル（韓国語・英語、表示順、表示/非表示）にあいさつ文を3件登録し、院長紹介ページを開くたびに表示中のものから `sample` で1つ選ぶ。管理画面で追加・編集・非表示にできる。

### 理由 / 이유
常連のお客様が何度見ても同じ文面だと印象が固定される。管理者が書き換えるだけで更新できるよう、コードではなくデータとして持つ。

### 注意 / 주의
ランダムなのでページキャッシュ（CDN 等）で HTML を長くキャッシュすると固定される。HTML は短い/ no-cache にし、静的ファイルと画像だけ長期キャッシュにする。

## ADR 0006: 論理削除と휴지통 / 논리 삭제와 휴지통

状態 / 상태: 採用 / 채택 (2026-10)

### 決定 / 결정
メニュー・分類・ブログ・イベントの「삭제」は `discarded_at` を入れる論理削除（`SoftDeletable`）。管理画面「휴지통」から復元／完全削除ができる。

### 理由 / 이유
管理者は非エンジニア。誤削除は必ず起きる。バックアップ復元（ADR 0002）は「全体を巻き戻す」ため、1件の誤削除には大げさ。

### 代替案 / 대안
- 確認ダイアログのみ: 押してしまったら戻せない。
- gem（discard / paranoia）: 小さな機能なので自前の10行で足りる。

## ADR 0007: アクセス分析は自前のクリック計測 +（任意）Cloudflare Web Analytics / 접속 분석

状態 / 상태: 採用 / 채택 (2026-10)

### 決定 / 결정
- **電話・道案内・予約のボタンのクリック数**を `click_events` に保存（種類・言語・ページ名・時刻のみ）。Cookie・IP・端末情報は保存しない。管理画面ダッシュボードに直近30日の件数を表示。
- ページ閲覧数は、独自ドメインを取得して Cloudflare を前に置く場合に Cloudflare Web Analytics（無料・Cookie なし）を任意で有効化できる。DuckDNS の間は使えない（`docs/operations.md`）。

### 理由 / 이유
目的は「電話してもらえたか」。個人情報を扱わなければ同意バナーが不要で、高齢の利用者にも優しい。Google Analytics は設定が重く、同意管理が必要になる。

### 注意 / 주의
サーバーが受けるのは件数だけ。ボット等で水増しされうるため、あくまで目安として使う。

## ADR 0008: 画像はアップロード時に WebP へ変換・縮小 / 이미지는 업로드 시 WebP 변환·축소

状態 / 상태: 採用 / 채택 (2026-10)

### 決定 / 결정
`image_processing`（libvips）で、アップロード時に WebP へ変換し長辺 1600px 以下・品質 82 に縮小（EXIF の位置情報は削除）。5MB 超の元ファイルは処理せず検証エラー。表示は用途別の variant、`loading="lazy"`（ファーストビューの画像は `eager` + `fetchpriority=high`）。GIF は変換しない。

### 理由 / 이유
転送量・ディスク・ LCP の改善。スマホ写真（数MB）をそのまま載せると遅い。libvips は ImageMagick よりメモリが少ない。

## ADR 0009: 例外はメールで通知（gem なし）/ 예외는 이메일로 알림

状態 / 상태: 採用 / 채택 (2026-10)

### 決定 / 결정
`Rails.error` の購読者（`config/initializers/error_notifier.rb`）で、未処理の例外を SMTP メールで `ERROR_NOTIFY_EMAIL` に送る。同種のエラーは10分に1回まで。`ERROR_NOTIFY_EMAIL` と `SMTP_ADDRESS` が未設定なら何もしない。

### 理由 / 이유
無料の監視（UptimeRobot で `/up`）は「落ちたか」しか分からない。500 エラーの原因は通知が必要。Sentry 等は無料枠・外部送信・設定が増える。まずは最小で。

### 限界 / 한계
メール送信自体が失敗すると通知されない。ログは `docker logs`（json-file 10MB×3）に残る。

## ADR 0010: 管理画面を自作する（Wix / Squarespace 等を使わない）/ 관리자 화면 직접 개발

状態 / 상태: 採用 / 채택 (2026-10)

### 決定 / 결정
Rails で管理画面を自作する。「1画面でのその場編集・大きなボタン・韓国語」に絞る。

### 比較 / 비교
| | 自作 (Rails) | Web ビルダー (Wix 等) |
|---|---|---|
| 初期コスト | 高い（開発時間） | 低い |
| 月額 | ほぼ 0 円 | 月 1,000〜3,000 円相当 |
| 操作の簡単さ | 美容室専用に絞れる（料金のその場編集） | 汎用で項目が多く、高齢の院長には複雑 |
| 多言語・SEO の細かい制御 | コードで自由 | テンプレートに依存 |
| データの持ち出し | 自分でバックアップ（SQLite） | ベンダー依存 |
| 継続保守 | 自分で担う（パッチ・バックアップ） | ベンダーが担う |

### 理由 / 이유
(1) 目的が「実際の事業用」かつ「設計を説明できるポートフォリオ」であること、(2) 料金表が一番更新される情報で、その場編集の価値が高いこと。
**弱点**: 保守を担う人がいなくなると止まる。運用ドキュメント（docs/operations.md）と ADR でその引き継ぎコストを下げる。

## ADR 0011: CSS は純粋な CSS、テストは Minitest / CSS는 순수 CSS, 테스트는 Minitest

状態 / 상태: 採用 / 채택 (2026-10)

### 決定 / 결정
- **CSS**: フレームワーク無し（`app/assets/stylesheets/application.css`、色は `:root` の変数のみ）。ページ数が4つで、アクセシビリティ（文字 18px 以上・コントラスト・ボタン 48px 以上）を数値で一元管理したい。Tailwind はビルド工程と依存が増える。
- **テスト**: Minitest（Rails 標準、追加 gem なし）。統合テスト中心（管理画面の操作・公開ページ・翻訳の一貫性）。RSpec は DSL の学習コストと依存が増える一方、この規模では利点が小さい。

### 守るルール
`test/i18n_consistency_test.rb`: 翻訳キー漏れ、`%{変数}` の不一致、公開ビューへの韓国語の直書きを検出する。
