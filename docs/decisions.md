## ADR 0001: SQLite を本番でも使う

状態: 採用（2026-10）

### 背景
- 街の美容室のサイト。アクセスは1日数十〜数百、書き込みは管理者1人のみ。月額コストは「ほぼ無料」が条件。
- 動かす環境は 1GB クラスの小さな VM（AWS Lightsail 等）。PostgreSQL を同居させるとそれだけで数百 MB を使う。

### 決定
SQLite（WAL モード、`busy_timeout=5000ms`、`synchronous=normal`）を開発・本番の両方で使う。Rails 8 標準の Solid Cache / Queue / Cable も SQLite で動かす（Redis 不要）。

### 検討した代替案
| 案 | 採用しなかった理由 |
|---|---|
| PostgreSQL（同一 VM） | メモリ消費が大きい。管理するものが1サーバー2プロセスに増える |
| Cloud SQL / マネージド DB | 無料枠がない。月額が目的の予算を超える |
| PostgreSQL（外部の無料プラン） | 海外リージョンで遅延する。無料枠の停止・消去のリスクがある |

### 結果・トレードオフ
- 利点: 運用がファイル1つで済む。バックアップは Litestream で連続複製（ADR 0002）。開発と本番が同じ DB。
- 制約: 書き込みは直列（同時に1つ）。サーバーは1台のみで、スケールアウトできない。
- **切り替えの目安**: 管理者が複数人で同時に編集する、サーバーを2台以上にする、書き込みが常時ある、のいずれかになったら PostgreSQL へ移行する（ActiveRecord を使っているのでコード変更は小さい）。

## ADR 0002: Litestream で S3 にバックアップ

状態: 採用（2026-10）

### 背景
SQLite は「ファイル」なので、ディスクが壊れるとデータがすべて消える。スナップショット（日次）では最大1日分を失う。

### 決定
- Litestream で primary DB の WAL を約10秒ごとに AWS S3（ソウル）へ複製する（GCS も同じ設定で可）。保持期間は 72 時間。
- 複製するのは **primary のみ**。cache は再生成できる、queue / cable は一時データのため対象外（`config/litestream.yml`）。
- 認証は、**そのバケットだけ**に権限を絞った IAM ユーザーのキー（`.env` に保存。AWS ルートのキーは使わない）。
- コンテナ起動時に DB がなければ自動で復元する（`bin/docker-entrypoint`）。
- **画像ファイル（Active Storage）は Litestream の対象外。** `/var/lib/eunpa/files` を別途バックアップする（`docs/operations.md` 参照: 日次の `aws s3 sync`）。

### 復元テスト
`deploy/restore-test.sh` で「ディスク消失 → 再起動 → 自動復元」を実機（Docker）で確認済み。結果は `docs/operations.md` に記録。S3 では URL を `s3://...` に変えるだけ（GCS も同様）。

### 代替案
- 日次の `sqlite3 .backup` + cron: 最大24時間分の損失。手順が増える。
- Cloud SQL の自動バックアップ: 無料枠がない（ADR 0001）。

## ADR 0003: 多言語は韓国語・英語・日本語に限定

状態: 採用（2026-10）、改訂（2026-11）

### 背景
当初は ko / en / vi / ja の4言語を想定したが、翻訳を専門家に確認する手間と費用に対して利用者が少ない。主な客層（40〜70代の地元の方）は韓国語を使う。英語は外国人のお客様や採用担当者向け。

### 決定（2026-10）
- 公開 URL は `/ko` `/en`。固定の文言は `config/locales/{ko,en}.yml`、DB の内容は `*_ko` / `*_en` の列（`Translatable`）。英語が空なら韓国語を表示する（フォールバック）。
- ブログ本文と院長紹介の英訳は、**構造だけ用意して任意入力**にする。
- 英語の文言は **草稿**。公開前にネイティブの校閲が必要。
- vi / ja は削除した（マイグレーション `RemoveVietnameseAndJapaneseColumns`。**元に戻せない**ため、バックアップを取ってから実施）。

### 改訂（2026-11）: 日本語（ja）を追加
- 日本語のお客様への対応のため `ja` を追加した。公開 URL は `/ja`、固定の文言は `config/locales/ja.yml`、DB の翻訳は `*_ja` の列（マイグレーション `AddJapaneseColumns`）。
- 日本語は **草稿**で、ネイティブの校閲が必要。空なら韓国語で代替する（既存の規則と同じ）。vi は引き続き対象外。

### 将来
言語の追加は「ロケールファイル + `_xx` 列 + ルート制約」の3点。必要になった時点で再検討する。

## ADR 0004: 本番は Docker（Rails+Litestream コンテナ + Caddy）

状態: 採用（2026-10）

### 決定
- 本番は Rails+Litestream の **コンテナ1つ**（+ HTTPS 用の Caddy。DuckDNS は Cloudflare の背後に置けないため）。Puma（ワーカーなし・スレッド3）の中で Solid Queue を動かし（`SOLID_QUEUE_IN_PUMA`）、`litestream replicate -exec` が Rails を子プロセスとして起動する。
- **ビルドは GitHub Actions**（テスト → イメージ作成 → GHCR へ push）。VM では `docker compose pull && up -d` だけを行う。1GB の VM で `docker build` や `assets:precompile` を実行しない。
- イメージは multi-stage（コンパイラは最終イメージに入れない）、非 root（UID 1000）、`libjemalloc2` でメモリの断片化を抑える。`config/master.key` は `.dockerignore` で除外する（イメージに秘密を入れない）。
- 秘密の値は、VM の `.env`（`deploy/env.production.example`）と GitHub Secrets のみに置く。

### 代替案
| 案 | 理由 |
|---|---|
| Kamal | 強力だが、1 VM・1 コンテナには機能過多。学習コストと依存が増える |
| Kubernetes / Cloud Run | コスト・複雑さが目的に合わない（Cloud Run は SQLite の永続化と相性が悪い） |
| VM に直接 Ruby を入れる | 環境の差やパッチ管理が属人化する |

### メモリ実測
`deploy/measure-memory.sh`（メモリ上限 700MB）: 起動直後は約 214MB、1,000 リクエスト後は約 266MB。

## ADR 0005: 院長のあいさつ文を複数持ち、ランダムに表示

状態: 採用（2026-10）

### 決定
`owner_greetings` テーブル（韓国語・英語・日本語、表示順、表示/非表示）にあいさつ文を3件登録し、美容室紹介のページを開くたびに、表示中のものから `sample` で1つ選ぶ。管理画面で追加・編集・非表示にできる。

### 理由
常連のお客様が何度見ても同じ文面だと、印象が固定される。管理者が書き換えるだけで更新できるよう、コードではなくデータとして持つ。

### 注意
ランダムに選ぶため、ページキャッシュ（CDN 等）で HTML を長くキャッシュすると固定されてしまう。HTML は短く（または no-cache に）し、静的ファイルと画像だけを長期キャッシュにする。

## ADR 0006: 論理削除とゴミ箱

状態: 採用（2026-10）

### 決定
メニュー・分類・ブログ・イベントの「削除」は、`discarded_at` を入れる論理削除（`SoftDeletable`）にする。管理画面の「ゴミ箱」（韓国語表示は「휴지통」）から、復元または完全削除ができる。

### 理由
管理者は非エンジニアで、誤削除は必ず起きる。バックアップからの復元（ADR 0002）は「全体を巻き戻す」ため、1件の誤削除には大げさである。

### 代替案
- 確認ダイアログのみ: 押してしまったら戻せない。
- gem（discard / paranoia）: 小さな機能なので、自前の10行で足りる。

## ADR 0007: アクセス分析は自前のクリック計測 +（任意）Cloudflare Web Analytics

状態: 採用（2026-10）

### 決定
- **電話・道案内・予約のボタンのクリック数**を `click_events` に保存する（種類・言語・ページ名・時刻のみ）。Cookie・IP・端末情報は保存しない。管理画面のダッシュボードに、直近30日の件数を表示する。
- ページ閲覧数は、独自ドメインを取得して Cloudflare を前に置く場合に、Cloudflare Web Analytics（無料・Cookie なし）を任意で有効にできる。DuckDNS の間は使えない（`docs/operations.md`）。

### 理由
目的は「電話してもらえたか」。個人情報を扱わなければ同意バナーが不要で、高齢の利用者にも優しい。Google Analytics は設定が重く、同意の管理が必要になる。

### 注意
サーバーが受け取るのは件数だけ。ボットなどで水増しされうるため、あくまで目安として使う。

## ADR 0008: 画像はアップロード時に WebP へ変換・縮小

状態: 採用（2026-10）

### 決定
`image_processing`（libvips）で、アップロード時に WebP へ変換し、長辺 1600px 以下・品質 82 に縮小する（EXIF の位置情報は削除）。5MB を超える元ファイルは処理せず、検証エラーにする。表示は用途別の variant と `loading="lazy"` を使う（ファーストビューの画像は `eager` + `fetchpriority=high`）。GIF は変換しない。

### 理由
転送量・ディスク・LCP の改善のため。スマートフォンの写真（数 MB）をそのまま載せると遅い。libvips は ImageMagick よりメモリが少ない。

## ADR 0009: 例外はメールで通知（gem なし）

状態: 採用（2026-10）

### 決定
`Rails.error` の購読者（`config/initializers/error_notifier.rb`）で、未処理の例外を SMTP メールで `ERROR_NOTIFY_EMAIL` に送る。同種のエラーは10分に1回まで。`ERROR_NOTIFY_EMAIL` と `SMTP_ADDRESS` が未設定なら何もしない。

### 理由
無料の監視（UptimeRobot で `/up`）では、「落ちたか」しか分からない。500 エラーの原因は通知が必要である。Sentry などは、無料枠・外部送信・設定が増える。まずは最小の構成にする。

### 限界
メール送信そのものが失敗すると通知されない。ログは `docker logs`（json-file 10MB×3）に残る。

## ADR 0010: 管理画面を自作する（Wix / Squarespace 等を使わない）

状態: 採用（2026-10）

### 決定
Rails で管理画面を自作する。「1画面でのその場編集・大きなボタン・韓国語」に絞る。

### 比較
| | 自作 (Rails) | Web ビルダー (Wix 等) |
|---|---|---|
| 初期コスト | 高い（開発時間） | 低い |
| 月額 | ほぼ 0 円 | 月 1,000〜3,000 円相当 |
| 操作の簡単さ | 美容室専用に絞れる（料金のその場編集） | 汎用で項目が多く、高齢の院長には複雑 |
| 多言語・SEO の細かい制御 | コードで自由 | テンプレートに依存 |
| データの持ち出し | 自分でバックアップ（SQLite） | ベンダー依存 |
| 継続的な保守 | 自分で担う（パッチ・バックアップ） | ベンダーが担う |

### 理由
(1) 目的が「実際の事業用」かつ「設計を説明できるポートフォリオ」であること、(2) 料金表が最も更新される情報で、その場編集の価値が高いこと。
**弱点**: 保守を担う人がいなくなると止まる。運用ドキュメント（`docs/operations.md`）と ADR で、その引き継ぎコストを下げる。

## ADR 0011: CSS は純粋な CSS、テストは Minitest

状態: 採用（2026-10）

### 決定
- **CSS**: フレームワークなし（`app/assets/stylesheets/application.css`、色は `:root` の変数のみ）。ページ数が少なく、アクセシビリティ（文字 18px 以上・コントラスト・ボタン 48px 以上）を数値で一元管理したい。Tailwind はビルド工程と依存が増える。
- **テスト**: Minitest（Rails 標準、追加 gem なし）。統合テスト中心（管理画面の操作・公開ページ・翻訳の一貫性）。RSpec は DSL の学習コストと依存が増える一方、この規模では利点が小さい。

### 守るルール
`test/i18n_consistency_test.rb`: 翻訳キーの漏れ、`%{変数}` の不一致、公開ビューへの韓国語の直書きを検出する。
